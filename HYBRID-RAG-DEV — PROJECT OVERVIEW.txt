HYBRID-RAG-DEV — PROJECT OVERVIEW

Project Goal:
Build a Hybrid Retrieval-Augmented Generation (RAG) system capable of understanding legal documents using structured extraction, graph relationships, and vector retrieval.

System Vision:
Instead of traditional RAG, the system combines:

1. Structured metadata extraction
2. Graph-based structural reasoning
3. Semantic vector search (upcoming phase)
4. Orchestrated hybrid retrieval workflow (future)

Primary Use Case:
Legal Act and Section understanding with cross-references and contextual reasoning.

---

CORE TECHNOLOGY STACK

- FastAPI (API layer)
- Python backend
- Neo4j (Graph persistence — ACTIVE)
- Vector Database (semantic retrieval — planned)
- LLM-based structured extraction
- Deterministic identity utilities

(PostgreSQL structured storage deferred for future consideration.)

---

IDENTITY RULES (CRITICAL)

act_id:
Primary identity of an Act.
Must remain consistent across all system layers.

section_id:
Global identity shared across:
- Structured JSON
- Graph database
- Chunk layer
- Future vector database
- Retrieval responses

chunk_id:
Unique identifier for text chunks (used in future vector layer).

No layer may generate alternative identifiers outside the identity utility module.
