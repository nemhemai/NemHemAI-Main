METADATA CONTRACT (UPDATED STATUS)

Metadata validation occurs during structured extraction and
persistence validation layers.

Required Structured Fields:

- act_title
- act_id
- section_number
- section_id
- heading
- content

Rules:

- LLM does not generate system identifiers.
- act_id and section_id are generated deterministically.
- Schema must remain stable once finalized.

---

LLM EXTRACTION IMPLEMENTATION

File:
app/services/extraction.py

Model:
Ollama (llama3.1)

Process:

1. Prompt legal text
2. LLM generates JSON
3. Markdown and noise cleaned
4. JSON parsed safely
5. Schema validated
6. Deterministic section_id generation enforced

Output Format:

{
  act_id,
  act_title,
  sections: [
    {
      section_number,
      heading,
      content,
      clauses,
      section_id
    }
  ]
}

Strict Rule:
Extraction layer performs transformation only.
No database writes.

---

LLM WRAPPER

app/llm/ollama_client.py

CHUNK PREPARATION LAYER (DAY 3 ADDITION)

File:
app/ingestion/chunk_service.py

Purpose:
Prepare section content for future embedding layer.

Capabilities:

✔ Splits section content into overlapping text chunks
✔ Preserves act_id and section_id
✔ Generates deterministic chunk_id
✔ Ensures memory-safe chunk splitting
✔ No database writes
✔ No embedding generation

Chunk Output Format:

{
  chunk_id,
  act_id,
  section_id,
  text
}

Strict Rule:
Chunk layer prepares data only.
Vector storage and embeddings are not implemented yet.
