


GRIEVANCE AGENT
5-Day Production-Grade Implementation Plan

NemHem Enhanced Architecture v2  ·  Phase 1 Agent  ·  June 2026





Overview & Approach

This plan delivers a production-grade Grievance Agent in 5 focused working days. Each day has a clear theme, concrete tasks, code targets, and measurable deliverables. The agent follows the NemHem v2 architecture: PraisonAI orchestrates the end-to-end workflow; LlamaIndex + Qdrant handle policy retrieval; Neo4j surfaces precedents; OpenHuman adds urgency/tone intelligence; and Hermes captures institutional memory.

Task Breakdown
Morning (0–4 hrs): PraisonAI Agent Definition + Classification
Task 3.1 Define PraisonAI agent config
Role: 'Government Grievance Specialist'
Goal: 'Classify incoming citizen complaints, retrieve relevant policy sections, identify similar past cases, and produce a structured resolution ticket'
Tools: classify_grievance, retrieve_policy, find_precedents, draft_response
LLM: OllamaLLM(model='mistral:7b-instruct', base_url='http://ollama:11434')
Task 3.2 Build classify_grievance tool
Input: raw complaint text
Prompt: structured output JSON with category, sub_category, priority (HIGH/MEDIUM/LOW), department, sentiment
Categories: INFRASTRUCTURE, HEALTHCARE, EDUCATION, EMPLOYMENT, FINANCIAL, LEGAL, OTHER
Output parsed and validated via Pydantic model
Task 3.3 Write classification tests
10 sample complaints spanning all 7 categories
Assert: category matches expected label; priority is valid enum

Afternoon (4–8 hrs): Neo4j Graph Schema + Precedent Tool
Task 3.4 Design Neo4j graph schema
Node types: GrievanceCase, Department, PolicyClause, ResolutionAction, CitizenProfile
Relationships: BELONGS_TO (Case→Dept), RESOLVED_BY (Case→Action), CITES (Case→Clause), SIMILAR_TO (Case→Case)
Create indexes on GrievanceCase.category and GrievanceCase.status
Task 3.5 Seed Neo4j with historical cases
Import 50–100 anonymized past grievance records (or generate synthetic data)
Create SIMILAR_TO edges via cosine similarity on complaint embeddings
Link resolved cases to their ResolutionAction nodes
Task 3.6 Build find_precedents tool
Input: category, sub_category
Cypher query: MATCH (c:GrievanceCase)-[:RESOLVED_BY]->(a:ResolutionAction) WHERE c.category=$cat RETURN c, a LIMIT 5
Returns: list of similar cases with resolution actions and time-to-resolve
Task 3.7 Integration test: full Day 3 pipeline
POST a grievance → classification → policy retrieval → precedent lookup
Assert all three tools return non-empty results
